# 使用說明

在 Obsidian 按左側的 🎤 按鈕，就能錄下**電腦播放的聲音＋AirPods 麥克風**，存成 m4a，停止後自動插入筆記。
不需要切換音訊裝置，也不需要 BlackHole。

> [!info] 原廠錄音機和這顆按鈕的差別
> Obsidian 內建的「錄音機」只錄麥克風，錄不到電腦的聲音。
> 這顆按鈕是自寫的本機外掛「Meeting Recorder」（設定和命令面板顯示這個名稱），滑鼠移上去會顯示「錄音筆記：開始」。

## 怎麼用

1. 戴上 AirPods Max，打開要放錄音的筆記，游標停在要插入的位置
   - 游標在一行文字中間也沒關係，會接在那一行後面，不會把字切開；游標在 frontmatter 裡就接在 frontmatter 後面
   - 焦點不在筆記上時（例如正在用終端機），會寫進**最近用過的那篇筆記**，「準備中」的通知會寫出是哪一篇
2. 按左側 🎤，選「只錄音」或「錄音＋錄 App 畫面…」（或命令面板 →「Meeting Recorder: 開始錄音」／「開始錄音＋錄 App 畫面」）
   - 先跳出「準備中…」：AirPods 從聽音樂切到通話模式要 **4～10 秒**，這段時間的聲音錄不到
   - 跳出「● 開始收音」才真的在錄。AirPods 已經在通話模式時（例如 Teams 開著），幾乎是立刻開始
   - 如果有在設定檔排除某個 App，而它正在播放，會跳出 ⚠️ 提醒：這次錄不到它的聲音
   - 錄音中按鈕會變成紅色方塊；**右下角狀態列會顯示「● 錄音 12:34」**，看得到錄了多久，點它也可以停止
3. 結束時再按一次紅色方塊。錄音檔和逐字稿都放在**開始錄音時那篇筆記**（完全沒有打開的筆記就自動新建「錄音 日期 時間.md」）
   - 錄音中把那篇筆記改名、搬資料夾都沒關係，逐字稿會跟著走；筆記被刪掉的話，會另開一篇「錄音 日期 時間.md」接著寫

## 逐字稿（2026-11-13 起）

筆記裡會出現這樣一段：

```markdown
### 🎙️ 錄音 2026-11-13 12:00
![[Recording 20261113120049.m4a]]
- `00:00` **對方**：今天的會議主要討論三件事……
- `00:25` **我**：……
```

| 階段 | 標題後面顯示 | 逐字稿來源 |
| :-- | :-- | :-- |
| 錄音中 | （錄音中，逐字稿即時更新） | Apple 內建語音辨識（zh-TW，本機）。約每 15 秒出一段，比講話晚 10～20 秒；英文術語常聽錯 |
| 按停止後 | （逐字稿 whisper 精修中…） | 錄音檔插到標題下方；背景跑 whisper |
| 精修完成 | （沒有括號） | whisper large-v3-turbo（本機）＋ opencc 轉台灣用字。**整段取代即時版** |

- **對方**＝電腦播出來的聲音（講師、開會的其他人），**我**＝麥克風。對方有好幾個人時不會再細分
- 精修速度：實測 10 分鐘的錄音 19 秒（M1 Max）；1 小時推估 2～4 分鐘。整場沒開口的麥克風會直接跳過。精修一次只跑一場，錄下一段不受影響，只是要排隊
- 錄音中可以在同一篇筆記照常打字。按開始後游標會停在逐字稿區塊**下面**，直接打字、貼圖就好
- 如果你把字打在逐字稿區塊**裡面**（兩行隱藏標記之間），精修時會保留，放在逐字稿後面；錄音中刪掉的截圖也不會被放回來
- 精修失敗時，標題會寫「whisper 精修失敗，以下是即時逐字稿」，暫存的聲音檔會留著。重試：命令面板 →「Meeting Recorder: 補做沒完成的逐字稿精修」
- 錄音中筆記裡會有 `%%course-rec … start%%`／`end%%` 兩行隱藏標記，標示逐字稿的位置，精修完成後自動移除。不小心刪掉的話，即時逐字稿會停止寫入，但精修完的逐字稿仍會加在筆記最後面
- 暫存空間：每小時約 230 MB 的 WAV（兩路各 115 MB，從 16 kHz 16-bit 算出），精修完就刪掉

## 截圖與時間（2026-11-13 起）

**錄音中貼進這篇筆記的截圖，會自動對上錄音時間：**

```markdown
- `00:12` 📷 ![](attachments/Pasted image 20261113121930.png)
  > [!quote]- 截圖文字
  > Sprint 23 架構檢討
  > • API Gateway 改用 OAuth 2.0 authentication
- `00:16` **對方**：第三，下週要跟客戶 demo……
```

- 貼的那一行**只有圖片**時，會整行搬進逐字稿、依時間排好；圖跟文字寫在同一行的就不動，逐字稿裡另外放一份
- 只處理**錄音中**貼進**這篇錄音筆記**的圖；貼到別篇筆記、或錄音前後貼的都不管
- 圖下方的「截圖文字」是 Mac 內建文字辨識（Vision，本機）讀出來的，預設摺疊；Obsidian 搜尋找得到
- 截圖文字裡的**英文術語會餵給 whisper 當提示**，投影片上的專有名詞比較不會聽錯。實測同一段錄音：沒提示時 Sprint 被聽成 Spring，有提示時正確（但不是每次都有效）
- whisper 精修時截圖會保留在原本的時間位置

**點逐字稿的時間就從那裡播放錄音：**

- 點 `` `12:34` `` → 從 12:34 開始播放這段逐字稿上方最近的那個錄音檔；再點同一個時間就停止
- 編輯模式、閱讀模式都可以點（閱讀模式的時間有虛線底線）；要把游標移進時間裡編輯，按住 ⌘ 再點
- 命令面板也有「Meeting Recorder: 停止播放錄音」

> [!info] 預設所有 App 的聲音都錄
> 預設只要有 App 發出聲音就錄進去，不挑 App，會議軟體的聲音也錄得到。**用在會議時，錄音前請先告知對方，並遵守主辦方與所在單位的規定。**
> 有不想錄的 App（例如通知音很吵的程式），再把它的 bundle ID 加進設定檔的 `excludeBundlePrefixes`；
> 排除的 App 正在播放時，按開始會跳出 ⚠️ 提醒。
> 實測：預設下 Teams 的聲音錄得到；把 Teams 加進排除名單時完全錄不到。

## 螢幕錄影（2026-11-13 起）

按 🎤 選「**錄音＋錄 App 畫面…**」：錄音先開始，接著跳出 macOS 的選擇視窗，選要錄的 **App 或單一視窗**。

- **只錄選到的那個 App**：其他 App、通知、桌面都不會入鏡；被其他視窗擋住也照樣錄得到
- **有開 AnnotateScreen 時，畫的標註會一起錄進去**（0.12.3 起）：選 App 就錄「那個 App＋標註」，選單一視窗就錄「那個視窗＋標註」、只保留視窗範圍內的部分。AnnotateScreen 的工具列與提示不會入鏡；錄到一半才打開 AnnotateScreen 也會跟上（約 2 秒內）
- 錄影中可以從選單列的螢幕分享圖示換成別的 App；選擇視窗按取消就只錄音
- 畫質以投影片為主：每秒 5 格、長邊縮到 1920×1080 以內、HEVC。檔案大小推估每小時 200～500 MB
- 錄影檔存在 **下載／螢幕錄影**，檔名是「筆記名稱 日期 時間.mp4」，**停止後會把錄音合進去**，影片自己就有聲音。你過一陣子要刪掉它沒關係
- 錄音檔、投影片截圖照樣放在 vault 裡，錄影刪掉後逐字稿和投影片都還在

**錄完後自動截投影片：**

```markdown
### 🎙️ 錄音 2026-11-13 14:00
![](attachments/Recording 20261113140000.m4a)
🎬 [錄影：會議筆記 2026-11-13 1400.mp4](file:///…/Downloads/螢幕錄影/…) %%video-offset 7.00%%
- `00:06` **對方**：今天的會議主要討論三件事。
- `00:07` 🖼️ ![](attachments/Slide 20261113140000-001.jpg)
  > [!quote]- 投影片文字
  > Sprint 23 架構檢討
- `00:10` **對方**：第一，Sprint 的進度目前落後兩天……
```

- 偵測畫面換頁：每頁穩定 2 秒以上才截，換頁動畫、捲動中、播影片時不會亂截；一直在動的小區域（會議視窗裡的人像）會自動忽略
- 每頁存一張 JPEG（約 60 KB）到 vault 的附件資料夾，辨識文字放在下方（預設摺疊），也會餵給 whisper 當詞彙提示
- 🖼️ 是自動截的投影片、📷 是你自己貼的截圖
- 逐字稿在截圖／投影片的時間點會斷開段落，圖會接在它那段話前面

**點時間跳到影片：** 有錄影、而且錄影檔還在時，點逐字稿的時間會用 **QuickTime Player** 打開錄影並跳到那個畫面（已經開著就直接跳）；錄影刪掉後，點時間就改成播錄音。

> [!tip] 錄影不要選 Obsidian 自己（或 Obsidian 所在的整個螢幕）
> 逐字稿每出一行字畫面就變一次，會被當成「換頁」一直截。2026-11-17 實際發生：30 分鐘的會議截了 103 張、筆記變成 666 KB（每張下面一百多行辨識文字）。錄音和逐字稿本身沒有壞，只是筆記很肥。要錄就選簡報或會議那個 App。

> [!success] 實測紀錄（2026-11-17）
> 4 頁簡報截到 4 張、點時間會跳到 QuickTime 的那個畫面；另有一場 30 分鐘的實錄，錄音與錄影長度相符（差 0.1 秒）。

> [!warning] 第一次使用要允許兩個權限
> 1. **螢幕錄製**：系統設定 → 隱私權與安全性 → 螢幕與系統錄音 → 允許 **Obsidian**。沒允許時會跳出「錄影失敗」，錄音不受影響
> 2. **控制 QuickTime**：第一次點時間跳影片時，macOS 會問「Obsidian 想要控制 QuickTime Player」→ 允許
>
> 新版 macOS 可能會定期再問一次是否繼續允許錄螢幕，頻率不確定。

## AnnotateScreen 截圖自動收進筆記（2026-11-13 起）

[AnnotateScreen](https://github.com/FengQing-TW/annotate-screen)（螢幕標註工具）按 ⌃⌥S 截圖、存到「下載」之後，外掛會自動：

- 把 `AnnotateScreen_日期_時間.png` **搬進目前筆記的附件資料夾**，插在游標那一行的下一行；「下載」裡不留
- **錄音中**：放進錄音那篇的逐字稿，時間是**按下截圖的那一刻**，並辨識圖中文字（跟自己貼的截圖一樣用 📷）
- 焦點不在筆記上（例如正在用簡報或終端機）時，收進最近用過的那篇筆記；完全沒有打開的筆記就留在「下載」
- Obsidian 開著才會收；外掛啟動前就在「下載」裡的舊截圖不會動
- 「下載」那份要等**確定插進筆記之後**才刪；檔案還沒寫完的話 5 秒後會再試一次，兩次都不行就留在「下載」並跳通知
- 暫停／恢復：命令面板 →「Meeting Recorder: 開啟／暫停自動收 AnnotateScreen 截圖」（記在外掛設定，重開 Obsidian 也維持）

> [!note] 跟 AnnotateScreen 的約定
> 外掛靠「下載資料夾＋檔名格式」辨認截圖。AnnotateScreen 改了存檔位置或檔名，就收不到了。這條約定也寫在 AnnotateScreen 的 README。
> AnnotateScreen 現在有三種截圖：⌃⌥S 整個螢幕、⌃⌥R 自己拖範圍、⌃⌥E 點選視窗（2026-11-13 起），三種都會自動收進筆記。

## 錄出來的檔案

| 項目 | 內容 |
| :-- | :-- |
| 格式 | m4a（AAC 立體聲），電腦聲音是立體聲，你的聲音左右都有 |
| 位置 | 依 Obsidian 的附件設定，目前是筆記所在資料夾的 `attachments/` |
| 檔名 | `Recording 年月日時分秒.m4a`，跟原廠錄音機同一種命名方式 |
| 大小 | 開著麥克風時是 24 kHz，實測位元率約 69 kbps，約 **31 MB／小時**（推估 ±20%）；關掉麥克風時是 48 kHz、96 kbps，約 43 MB／小時（推估） |
| 最長 | 4 小時自動停止並存檔，避免忘了停 |
| 防爆音 | 電腦聲音和麥克風相加後，超過約 -1.9 dBFS 的峰值會被平滑壓下來，永遠不會超過上限；講課的正常音量碰不到。存檔通知會顯示「防爆音作用 N 個取樣」，N 很大代表來源本身太大聲。驗證：`bin/course-recorder --selftest-limiter` |

> [!note] 音質
> AirPods 的麥克風一開，藍牙會切到通話模式（24 kHz），所以**電腦的聲音也會變成 24 kHz**。講課的聲音聽得清楚，音樂比較悶。
> 只需要電腦聲音、不需要錄自己時，把 `micGain` 設成 `0`，AirPods 會維持聽音樂的音質，開始錄音也不用等。

## 出狀況時會怎樣（2026-11-13 審查後加上）

| 狀況 | 會發生什麼 |
| :-- | :-- |
| 錄音中 Obsidian 被關掉或當掉 | 錄音程式 2 秒內發現、自己把錄音檔存好。**下次開 Obsidian 會自動補上**：把錄音檔插進筆記、跑 whisper 精修 |
| 精修到一半 Obsidian 被關掉 | 同上，下次啟動自動重跑（每場自動只試一次；之後用命令「補做沒完成的逐字稿精修」） |
| 錄音中耳機斷線、音訊裝置被換掉 | 6 秒內跳出 ⚠️「收音中斷了」，一直顯示到恢復為止。已錄的部分不受影響；接回來會自動繼續，之後截圖的時間會扣掉中斷的秒數 |
| 即時逐字稿自己掛掉 | 跳出 ⚠️ 提醒；錄音照常，停止後 whisper 仍會產生完整逐字稿 |
| 設定檔 `config.json` 寫錯 | 跳出 ⚠️ 提醒，這次用預設值（不會悄悄忽略） |
| 磁碟太慢寫不進去 | 存檔通知會多一句「⚠️ 寫檔失敗 N 次」 |
| 按停止後錄音程式卡住 | 45 秒後強制結束（錄音檔在收尾的第一步就已經寫好） |
| 精修好的逐字稿寫不進筆記（磁碟或 vault 暫時出錯） | 暫存留著、不會顯示完成；用命令「補做沒完成的逐字稿精修」重試（2026-11-13 審查後加上） |
| 補做過一次還是沒完成 | 每次開 Obsidian 會提醒一次有幾場、暫存佔多少 MB；不要了就刪 `~/.config/course-recorder/tmp/` 裡的資料夾 |
| 開 Obsidian 時上一場錄音還在收尾 | 每 30 秒再查一次（最多 5 次），收尾完自動補做 |
| 錄音沒有合進錄影檔 | 跳出 ⚠️ 提醒那支影片沒有聲音；錄音檔本身不受影響 |
| whisper 漏字 | 自動檢查兩種情形並單獨重跑：有聲音卻沒有逐字稿（4 秒以上）、一大段聲音只辨識出很少的字 |

**已知限制（沒有解的）：**

- 錄音程式本身被強制結束（`kill -9`）或整台電腦斷電：m4a 來不及收尾會無法播放。暫存的兩路 WAV 還在 `~/.config/course-recorder/tmp/`，逐字稿可以用「補做」命令救回來，但聲音要另外從 WAV 轉
- 「不錄某個 App」的名單是按下開始時決定的；錄音中才啟動的 App 不會被排除
- 收音中斷過（耳機斷線）又同時在錄影：錄影檔裡中斷之後的聲音會比畫面早，早的秒數等於中斷的長度。錄音檔和逐字稿的時間不受影響
- AirPods 在**聽音樂模式**下按開始：2026-11-17 實測正常（速度、音高正常，兩邊聲音都有）。最長的真實錄音是 2026-11-17 的 30 分鐘；**1 小時以上還沒有實測過**。程式會偵測取樣率中途改變並跳 ⚠️，但沒有實際遇過
- 截圖／投影片的辨識文字裡如果剛好有逐字稿的隱藏標記（截到 Obsidian 自己的畫面時會發生），舊版（0.10.0 以前）會把逐字稿的結尾認錯，後面的句子插錯位置、精修後留下殘段。2026-11-17 外掛 0.10.1 修掉：引用區塊裡的字不當標記，辨識文字裡的 `%%` 一律拆開

## 設定

設定檔：`~/.config/course-recorder/config.json`。沒有這個檔就用預設值；改完下一次錄音就生效。

```json
{
  "excludeBundlePrefixes": [],
  "micGain": 1.0,
  "bitRate": 96000
}
```

| 欄位 | 預設 | 說明 |
| :-- | :-- | :-- |
| `excludeBundlePrefixes` | `[]`（全部都錄） | 不錄這些程式的聲音（用 bundle ID 開頭比對），例如 `["com.microsoft.teams"]` 就是不錄 Teams。查 bundle ID：`~/.config/course-recorder/bin/course-recorder --list-processes` |
| `micGain` | `1.0` | 麥克風音量倍率；`0` = 不錄麥克風 |
| `bitRate` | `96000` | AAC 位元率；24 kHz 時編碼器實際用不到這麼高 |

## 疑難排解

| 狀況 | 先查 |
| :-- | :-- |
| 超過 10 秒還停在「準備中…」 | AirPods 有沒有連上；按停止後再按一次開始 |
| 錄到的只有我的聲音、沒有對方 | 設定檔有沒有把播放聲音的 App 排除掉（開始時會跳出 ⚠️ 提醒） |
| 跳出「一秒都沒收到聲音」 | 沒有存檔也沒有插入筆記；通常是 AirPods 在錄音中斷線 |
| 開頭幾秒沒錄到 | 正常：AirPods 切換模式的那 4～10 秒錄不到。先按開始，等「開始收音」再開始播放 |
| 錄音檔沒有插入筆記 | 開始錄音時沒有打開任何筆記；錄音檔仍在 vault 的附件資料夾，通知裡會顯示路徑 |
| 跳出「錄影失敗」 | 系統設定 → 隱私權與安全性 → 螢幕與系統錄音，Obsidian 有沒有打開；改完要重開 Obsidian |
| 跳出「錄影中斷了」 | 被錄的 App 關掉了；錄音照常，錄影到那裡為止 |
| 點時間沒有跳到影片 | 錄影檔是不是已經刪了或搬走了（會改播錄音）；或是 QuickTime 的控制權限被拒絕：系統設定 → 隱私權與安全性 → 自動化 → Obsidian → QuickTime Player |
| 投影片截太多或太少 | 換頁偵測的門檻在 `video_post.py` 開頭（NEW_CELLS、STABLE_CELLS），可以自己調整 |
| 跳出「麥克風 10 秒都沒有聲音」 | AirPods 沒連上時，系統會自動改用 MacBook 內建麥克風，但螢幕蓋著時它被硬體切斷。連上 AirPods 後停止、重新開始錄 |
| AnnotateScreen 截圖沒有進筆記 | 命令「開啟／暫停自動收 AnnotateScreen 截圖」是不是暫停了；第一次要允許 Obsidian 取用「下載」；有沒有打開的筆記 |
| 跳出「收音中斷了」 | 耳機是不是斷線、系統的輸出／輸入裝置是不是被換掉。接回來會自動繼續；不行就按停止再重新開始 |
| 標題一直停在「精修中…」 | 命令面板 →「Meeting Recorder: 補做沒完成的逐字稿精修」 |
| 跳出「沒有開始錄音」 | 通知裡會附上錯誤訊息；第一次使用時 macOS 可能會詢問「系統錄音」權限，要允許 |
| 錄到 Teams 以外不想要的聲音（例如通知音） | 把那個程式的 bundle ID 加進 `excludeBundlePrefixes` |

## 檔案在哪

| 檔案 | 用途 |
| :-- | :-- |
| `<vault>/.obsidian/plugins/meeting-recorder/` | 本機外掛：按鈕、命令、插入筆記 |
| `~/.config/course-recorder/course-recorder.swift` | 錄音程式原始碼 |
| `~/.config/course-recorder/bin/course-recorder` | 編譯後的錄音程式 |
| `~/.config/course-recorder/Info.plist` | 編譯時嵌入的權限說明文字 |
| `~/.config/course-recorder/config.json` | 設定（可以沒有） |
| `~/.config/course-recorder/transcribe.py` | 錄完後的 whisper 精修（Apple 內建 python3 跑，`-I` 隔離模式） |
| `~/.config/course-recorder/video_post.py` | 錄影後處理：錄音合進影片、偵測投影片換頁並截圖 |
| `~/Downloads/螢幕錄影/` | 螢幕錄影檔（可以自己刪） |
| `~/.config/course-recorder/ocr.swift`、`bin/ocr` | 截圖文字辨識（Vision，繁中＋英文）；編譯：`swiftc -O -swift-version 5 -o bin/ocr ocr.swift` |
| `~/.config/course-recorder/tmp/<時間>/` | 錄音中暫存的兩路 WAV 和 `session.json`（這場錄音的狀態：哪篇筆記、截圖、做到哪一步），精修完自動刪 |
| `~/Library/Application Support/whisper.cpp/models/ggml-large-v3-turbo.bin` | whisper 模型（1.6 GB） |
| `/opt/homebrew/bin/whisper-cli`、`/opt/homebrew/bin/opencc` | Homebrew 安裝的 whisper.cpp、繁簡轉換 |

修改原始碼後要重新編譯：

```
cd ~/.config/course-recorder && swiftc -O -swift-version 5 -o bin/course-recorder course-recorder.swift -Xlinker -sectcreate -Xlinker __TEXT -Xlinker __info_plist -Xlinker Info.plist
```

原理：macOS 14.4 起的 Core Audio process tap 可以直接抓系統播出的聲音，不管各 App 選了哪個喇叭。
程式把 tap 和預設麥克風放進同一個私有聚集裝置，用同一個時脈讀出、混音後寫成 AAC。這個聚集裝置在錄音結束時就會刪掉，不會出現在系統的聲音設定裡。

> [!note] 為什麼錄音程式自己會「播放無聲」
> 2026-11-13 實測（當時預設排除 Teams）：只有被排除的程式（Teams）在發聲時，tap 會整個停住，連麥克風都錄不到，第一版因此錄出 557 bytes 的空檔案。
> 換成用麥克風當時脈也沒用。最後的修法是讓錄音程式自己對輸出裝置持續播放無聲，系統就一直有一個「正在播放、沒被排除」的程式，tap 就會持續送資料。你聽不到這個無聲。

## 移除

1. Obsidian 設定 → 第三方外掛 → 停用並刪除「Meeting Recorder」
2. 刪掉 `~/.config/course-recorder/`
